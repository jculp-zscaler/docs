## Props

| Prop          | Type         | Default | Description                                                              |
| :------------ | :----------- | :------ | :----------------------------------------------------------------------- |
| `open`        | `boolean`    | —       | Controlled visibility.                                                   |
| `onClose`     | `() => void` | —       | Called on close button, overlay click, or <kbd>Esc</kbd>.                |
| `title`       | `string`     | —       | Modal heading. Required.                                                 |
| `dismissible` | `boolean`    | `true`  | When `false`, hides the close button and disables overlay/Esc dismissal. |
| `children`    | `ReactNode`  | —       | Body content and optional `Modal.Footer`.                                |

## Usage

- Reserve modals for decisions that block the task: confirmations, destructive actions, required input.
- Title as a question, footer as the answer: the primary button text should answer the title ("Delete firewall rule?" → "Delete rule").
- Never stack modals. If a flow needs multiple steps, use a full page.
- Set `dismissible={false}` only when closing would lose unrecoverable work.

## Accessibility

<AccordionGroup>
  <Accordion title="Keyboard and focus" icon="accessibility">
    | Key | Behavior |
    | :-- | :-- |
    | <kbd>Esc</kbd> | Closes the modal (when dismissible). |
    | <kbd>Tab</kbd> / <kbd>Shift\+Tab</kbd> | Cycles focus inside the modal (focus is trapped). |

    - Focus moves to the modal on open and returns to the trigger on close.
    - `role="dialog"` with `aria-modal="true"`; the title is the accessible name.

  </Accordion>
</AccordionGroup>
